DECIR:
Buenos días. Vamos a presentar Travel North, un proyecto para organizar la información de una agencia de viajes. La necesidad principal es administrar destinos, ofrecer paquetes turísticos y registrar reservas sin superar los cupos disponibles. También necesitamos consultar qué se está reservando y cómo cambia la actividad. El proyecto parte de la temática que trabajamos en las otras materias. 0:50 A 1:50 - LAS TRES APLICACIONES
PANTALLA: Mostrar brevemente la dirección de Gestión, cambiar al reporte JSON y luego al tablero. Regresar a Gestión.
DECIR:
La solución tiene tres aplicaciones Flask independientes. La API funciona en el puerto cinco mil y se encarga de las reglas, los datos y los cálculos. La interfaz de gestión funciona en el cinco mil uno y presenta los formularios. El tablero funciona en el cinco mil dos y muestra los resultados. La comunicación ocurre mediante solicitudes HTTP y respuestas JSON, como esta que vemos aquí. Cuando usamos un formulario, JavaScript envía los datos a la API. Python los valida y consulta o modifica SQLite. El tablero solicita el reporte a esa misma API. Por eso, ambos muestran información de una sola base de datos.

1:50 A 2:35 - MODELO Y REGLAS
PANTALLA: Abrir Paquetes. Señalar destinos, precio por persona y cupos del paquete elegido.
DECIR:
Las entidades principales son destinos, paquetes y reservas. Un paquete puede incluir varios destinos, y cada reserva pertenece a un paquete. SQLite conserva estas relaciones mediante claves foráneas. Las reservas pendientes y confirmadas ocupan cupo; las canceladas lo liberan. La API comprueba que el paquete esté disponible y que existan cupos suficientes. Además, calcula el total con el precio y la cantidad de personas. El usuario no escribe manualmente ese total ni la fecha de registro.

CINCO PREGUNTAS Y RESPUESTAS PARA DESPUÉS DEL GUION

1. ¿Qué hace Python en este proyecto?
Flask recibe las solicitudes de la API, ejecuta las validaciones y coordina las consultas SQL a SQLite. También sirve las páginas de gestión y analítica desde sus aplicaciones independientes. Chart.js dibuja las gráficas en el navegador.

2. ¿Por qué el navegador no accede directamente a SQLite?
La API centraliza el acceso y las reglas. Así, un dato pasa por las validaciones antes de almacenarse. El navegador trabaja con HTTP y JSON, sin abrir el archivo de la base de datos.

3. ¿Qué diferencia hay entre CRUD y analítica?
CRUD crea, consulta, modifica y elimina registros individuales. La analítica agrupa esos registros para obtener indicadores y comparaciones, como reservas por mes o valor por paquete.

4. ¿Por qué el valor confirmado no equivale a ingresos cobrados?
Porque el sistema registra reservas, pero no registra pagos. Confirmar una reserva permite calcular su valor; no demuestra que ese dinero haya sido recibido.

5. ¿Qué se reutilizó del proyecto de las otras materias?
La temática de Travel North, las entidades, sus relaciones y los procesos de gestión. Esta entrega es una adaptación con tres aplicaciones Flask y SQLite; no depende de mantener funcionando el backend Java del proyecto original.
